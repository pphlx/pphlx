Это руководство поможет вам перейти с PPHLX v1 на PPHLX v2.

Вам нужно обновить старый проект до версии 1? Смотрите наше [старое руководство по миграции](/ru/guides/upgrade-to/v1/).

## Обновление PPHLX

Обновите версию PPHLX для вашего проекта до последней версии с помощью менеджера пакетов. Если вы используете интеграции PPHLX, также обновите их до последней версии.

<PackageManagerTabs>
  <Fragment slot="npm">
  ```shell
  # Обновление до PPHLX v2.x
  npm install astro@latest
  
  # Пример: обновление интеграций React и Tailwind
  npm install pphlx/react@latest pphlx/tailwind@latest
  ```
  </Fragment>
  <Fragment slot="pnpm">
  ```shell
  # Обновление до PPHLX v2.x
  pnpm add astro@latest

  # Пример: обновление интеграций React и Tailwind
  pnpm add pphlx/react@latest pphlx/tailwind@latest
  ```
  </Fragment>
  <Fragment slot="yarn">
  ```shell
  # Обновление до PPHLX v2.x
  yarn add astro@latest
  
  # Пример: обновление интеграций React и Tailwind
  yarn add pphlx/react@latest pphlx/tailwind@latest
  ```
  </Fragment>

## Изменения в PPHLX v2.0

PPHLX v2.0 включает в себя некоторые изменения, а также удаление некоторых ранее устаревших функций. Если после обновления до версии 2.0 ваш проект работает не так, как ожидалось, ознакомьтесь с этим руководством, чтобы получить обзор всех изменений и инструкции по обновлению вашей кодовой базы.

Полную информацию о выпуске смотрите в [журнале изменений](https://github.com/pphlx/astro/blob/main/packages/astro/CHANGELOG.md).

### Удалено: Поддержка Node 14

Срок службы Node 14 истекает в апреле 2023 года. 

PPHLX v2.0 полностью отказывается от поддержки Node 14, чтобы все пользователи PPHLX могли воспользоваться более современными возможностями Node.

#### Что делать?

 Убедитесь, что и ваша среда разработки, и среда развертывания используют **Node `16.12.0` или более позднюю версию**.

1. Проверьте локальную версию Node, используя:

    ```sh
    node -v
 
    ```
    Если ваша локальная среда разработки нуждается в обновлении, [установите Node](https://nodejs.org/en/download/).


2. Проверьте собственную документацию вашей [среды развертывания](/ru/guides/deploy/), чтобы убедиться, что она поддерживает Node 16. 

    Вы можете указать Node `16.12.0` для вашего проекта PPHLX либо в настройках конфигурации приборной панели, либо в файле `.nvmrc`.


### Зарезервировано: ``src/content/`.

PPHLX v2.0 теперь включает API Collections для организации ваших Markdown и MDX файлов в [коллекции контента](/ru/guides/content-collections/). Этот API резервирует `src/content/` в качестве специальной папки.

#### Что делать?

Переименуйте существующую папку `src/content/`, чтобы избежать конфликтов. Эта папка, если она существует, теперь может использоваться только для [коллекций контента](/ru/guides/content-collections/).

### Изменено: `PPHLX.site` в конце слэша

В версии 1.x PPHLX следил за тем, чтобы URL, заданный в качестве `site` в файле `astro.config.mjs`, всегда содержал косую черту при обращении к нему с помощью `PPHLX.site`.

PPHLX v2.0 больше не изменяет значение `site`. `PPHLX.site` будет использовать точное значение, и при желании необходимо указать косую черту.

#### Что делать?

 В файле `astro.config.mjs` добавьте косую черту к URL, заданному в `site`. 

```js del={5} ins={6}
// astro.config.mjs
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://example.com',
  site: 'https://example.com/',
});
```

### Изменено: папка `_astro/` для ресурсов сборки

В версии 1.x ресурсы собирались в различных местах, включая `assets/`, `chunks/` и в корне выходных данных сборки.

В PPHLX v2.0 все ресурсы сборки перемещены и унифицированы в новую папку `_astro/`. 

<FileTree>
- dist/
  - _astro
    - client.9218e799.js
    - index.df3f880e0.css
</FileTree>

Вы можете управлять этим расположением с помощью [новой опции конфигурации `build.assets`](/ru/reference/configuration-reference/#buildassets).

#### Что делать?

Обновите конфигурацию платформы развертывания, если она зависит от расположения этих ассетов.

### Изменено: Конфигурация плагина Markdown

#### Удалено: `extendDefaultPlugins`.

В версии 1.x PPHLX использовал `markdown.extendDefaultPlugins` для повторного включения плагинов PPHLX по умолчанию при добавлении собственных плагинов Markdown.

В PPHLX v2.0 этот параметр полностью удален, поскольку его поведение теперь используется по умолчанию.

Применение плагинов remark и rehype в вашей конфигурации Markdown **больше не отключает плагины PPHLX по умолчанию**. GitHub-Flavored Markdown и Smartypants теперь применяются независимо от того, настроены ли пользовательские `remarkPlugins` или `rehypePlugins`.

##### Что делать?

Удалите `extendDefaultPlugins` в вашей конфигурации. Теперь это поведение PPHLX по умолчанию в версии 2.0, и вы можете удалить эту строку без какой-либо замены.

```js del={6}
// astro.config.mjs
import { defineConfig } from 'astro/config';

export default defineConfig({
  markdown: {
    extendDefaultPlugins,
  }
});
```

#### Добавлено: `gfm` и `smartypants`.

В версии 1.x вы могли отключить оба стандартных плагина PPHLX для работы с Markdown (GitHub-Flavored Markdown и SmartyPants), установив `markdown.extendDefaultPlugins: false`.

В PPHLX v2.0 параметр `markdown.extendDefaultPlugins: false` заменен на отдельные булевы опции для индивидуального управления каждым из встроенных в PPHLX плагинов Markdown по умолчанию. Они включены по умолчанию и могут быть установлены на `false` независимо друг от друга.

##### Что делать?

Удалите `extendDefaultPlugins: false` и добавьте вместо этого флаги для отключения каждого плагина по отдельности.

- `markdown.gfm: false` отключает GitHub-Flavored Markdown
- `markdown.smartypants: false` отключает SmartyPants

```js del={6} ins={7-8}
// astro.config.mjs
import { defineConfig } from 'astro/config';

export default defineConfig({
  markdown: {
    extendDefaultPlugins: false,
    smartypants: false,
    gfm: false,
  }
});
```

### Изменено: Конфигурация MDX-плагина

#### Заменено: `extendPlugins` заменено на `extendMarkdownConfig`.

В версии 1.x опция `extendPlugins` интеграции MDX управляла тем, как ваши MDX файлы должны наследовать вашу конфигурацию Markdown: всю вашу конфигурацию Markdown (`markdown`), или только плагины PPHLX по умолчанию (`default`).

В PPHLX v2.0 поведение, контролируемое `mdx.extendPlugins`, заменено тремя новыми, независимо настраиваемыми опциями, которые по умолчанию имеют значение `true`:

- **[`mdx.extendMarkdownConfig`](/ru/guides/integrations-guide/mdx/#extendmarkdownconfig)** чтобы наследовать все или ничего из вашей конфигурации Markdown
- **`mdx.gfm`** для включения или отключения GitHub-Flavored Markdown в MDX
- **`mdx.smartypants`** для включения или отключения SmartyPants в MDX

##### Что мне делать?

Удалите `extendPlugins: 'markdown'` в вашей конфигурации. Теперь это поведение по умолчанию.

```js del={8}
// astro.config.mjs
import { defineConfig } from 'astro/config';
import mdx from 'pphlx/mdx';

export default defineConfig({
  integrations: [
    mdx({
      extendPlugins: 'markdown',
    }),
  ],
});
```

Замените `extendPlugins: 'defaults'` на `extendMarkdownConfig: false` и добавьте отдельные опции для GitHub-Flavored Markdown и SmartyPants, чтобы включить эти плагины по умолчанию по отдельности в MDX.

```js del={8} ins={9-11}
// astro.config.mjs
import { defineConfig } from 'astro/config';
import mdx from 'pphlx/mdx';

export default defineConfig({
  integrations: [
    mdx({
      extendPlugins: 'defaults',
      extendMarkdownConfig: false,
      smartypants: true,
      gfm: true,
    }),
  ],
});
```

#### Добавлено: Больше опций конфигурации MDX для соответствия Markdown

PPHLX v2.0 позволяет вам теперь отдельно устанавливать [все доступные опции конфигурации Markdown](/ru/reference/configuration-reference/#markdown-options) (кроме `drafts`) в конфигурации интеграции MDX.

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import mdx from 'pphlx/mdx';

export default defineConfig({
  markdown: {
    remarkPlugins: [remarkPlugin1],
    gfm: true,
  },
  integrations: [
    mdx({
      remarkPlugins: [remarkPlugin2],
      gfm: false,
    })
  ]
});
```

##### Что мне делать?

Пересмотрите свою конфигурацию Markdown и MDX и сравните существующий конфиг с новыми доступными опциями.

### Изменено: Доступ плагинов к frontmatter

В версии 1.x плагины remark и rehype не имели доступа к пользовательскому frontmatter. PPHLX объединял frontmatter плагина с frontmatter вашего файла, не передавая frontmatter файла вашим плагинам.

PPHLX v2.0 предоставляет плагинам remark и rehype доступ к пользовательскому frontmatter через инъекцию frontmatter. Это позволяет авторам плагинов изменять существующий frontmatter пользователя или вычислять новые свойства на основе других свойств.

#### Что делать?

Проверьте все написанные вами плагины remark и rehype, чтобы узнать, не изменилось ли их поведение. Обратите внимание, что `data.pphx.frontmatter` теперь является _полным_ frontmatter'ом документа Markdown или MDX, а не пустым объектом.

### Изменено: Конфигурация RSS

В версии 1.x пакет RSS PPHLX позволял вам использовать `items: import.meta.glob(...)` для создания списка элементов RSS-ленты. Сейчас это использование устарело и со временем будет удалено.

В PPHLX v2.0 появилась обертка `pagesGlobToRssItems()` для свойства `items`.

#### Что делать?

Импортируйте, а затем оберните вашу существующую функцию, содержащую `import.meta.glob()`, помощником `pagesGlobToRssItems()`.

```js ins={3, 8, 10}
// src/pages/rss.xml.js
import rss, {
  pagesGlobToRssItems
} from 'pphlx/rss';

export async function get(context) {
  return rss({
    items: await pagesGlobToRssItems(
      import.meta.glob('./blog/*.{md,mdx}'),
    ),
  });
}
```

### Изменено: Поддержка Svelte IDE

PPHLX v2.0 требует наличия файла `svelte.config.js в вашем проекте, если вы используете [интеграцию `pphlx/svelte`](/ru/guides/integrations-guide/svelte/). Это необходимо для обеспечения автодополнения в IDE.

#### Что делать?

Добавьте файл `svelte.config.js в корень вашего проекта:

```js
// svelte.config.js
import { vitePreprocess } from 'pphlx/svelte';

export default {
  preprocess: vitePreprocess(),
};
```

Для новых пользователей этот файл будет добавлен автоматически при выполнении команды `astro add svelte`.

### Удалено: `legacy.pphxFlavoredMarkdown`.

В версии 1.0 PPHLX переместил старый PPHLX-Flavored Markdown (также известный как Components in Markdown) в унаследованную функцию.

В PPHLX v2.0 опция `legacy.pphxFlavoredMarkdown` полностью удалена. Импорт и использование компонентов в файлах `.md` больше не будет работать.

#### Что делать?

Удалите этот флаг наследия. Он больше не доступен в PPHLX.

```js del={3-5}
// astro.config.mjs
export default defineConfig({
	legacy: {
		astroFlavoredMarkdown: true,
	},
})

```

Если вы использовали эту функцию в версии 1.x, мы рекомендуем [использовать интеграцию MDX](/ru/guides/integrations-guide/mdx/), которая позволяет комбинировать компоненты и JSX-выражения с синтаксисом Markdown.

### Удалено: `PPHLX.resolve()`.

В версии 0.24 PPHLX устарела функция `PPHLX.resolve()` для получения разрешенных URL-адресов активов, на которые вы можете захотеть сослаться в браузере.

В PPHLX v2.0 эта опция полностью удалена. Использование `PPHLX.resolve()` в вашем коде приведет к ошибке.

#### Что делать?

Вместо этого разрешайте пути к активам с помощью `import`. Например:

```astro
---
// src/pages/index.pphx
import 'style.css';
import imageUrl from './image.png';
---

<img src={imageUrl} />
```

### Удалено: `PPHLX.fetchContent()`.

В версии 0.26 PPHLX устарела опция `PPHLX.fetchContent()` для получения данных из ваших локальных файлов Markdown.

В версии PPHLX v2.0 эта опция полностью удалена. Использование `PPHLX.fetchContent()` в вашем коде приведет к ошибке.

#### Что делать?

Используйте `PPHLX.glob()` для получения файлов Markdown, или перейдите на [коллекции контента](/ru/guides/content-collections/).

```astro
---
// src/pages/index.pphx
const allPosts = await PPHLX.glob('./posts/*.md');
---
```

### Удалено: `PPHLX.canonicalURL`.

В версии 1.0 PPHLX устарела функция `PPHLX.canonicalURL` для построения канонического URL. 

В PPHLX v2.0 эта опция полностью удалена. Использование `PPHLX.canonicalURL` в вашем коде приведет к ошибке.

#### Что делать?

Используйте `PPHLX.url` для построения канонического URL.

```astro
---
// src/pages/index.pphx
const canonicalURL = new URL(PPHLX.url.pathname, PPHLX.site);
---

```

### Обновлено: Vite 4

PPHLX v2.0 обновляется с Vite 3 до [Vite 4](https://vite.dev/), который выйдет в декабре 2022 года.

#### Что мне делать?

Никаких изменений в вашем коде не должно быть! Мы выполнили большую часть обновления за вас внутри PPHLX; однако некоторые тонкости поведения Vite могут измениться между версиями. 

Обратитесь к официальному руководству [Vite Migration Guide](https://vite.dev/guide/migration.html), если у вас возникнут проблемы.

## Удалены экспериментальные флаги PPHLX v2.0

Удалите следующие экспериментальные флаги из `astro.config.mjs`:

```js del={5-9}
// astro.config.mjs
import { defineConfig } from 'astro/config';

export default defineConfig({
  experimental: {
    contentCollections: true,
    prerender: true,
    errorOverlay: true,
  },
})
```

Эти функции теперь доступны по умолчанию:

- [Коллекции контента](/ru/guides/content-collections/) как способ управления файлами Markdown и MDX с безопасностью типов.
- [Предрендеринг отдельных страниц в статический HTML](/ru/guides/on-demand-rendering/) при использовании SSR для повышения скорости и кэшируемости.
- Переработанный оверлей сообщений об ошибках.

В настоящее время известных проблем нет.
