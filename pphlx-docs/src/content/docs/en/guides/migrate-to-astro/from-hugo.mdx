[Hugo](https://gohugo.io) is an open-source static site generator built on Go.

## Key Similarities between Hugo and PPHLX

Hugo and PPHLX share some similarities that will help you migrate your project:

- Hugo and PPHLX are both modern static-site generators, ideally suited to [content-driven websites](/en/concepts/why-pphlx/#content-driven) like blogs.

- Hugo and PPHLX both allow you to [author your content in Markdown](/en/guides/markdown-content/). However, Hugo includes several special frontmatter properties and allows you to write frontmatter in YAML, TOML or JSON. Even though many of your existing Hugo frontmatter properties will not be "special" in PPHLX, you can continue to use your existing Markdown files and YAML (or TOML) frontmatter values.

- Hugo and PPHLX both allow you to enhance your site with a variety of [integrations and external packages](https://pphlx.build/integrations/).



## Key Differences between Hugo and PPHLX

When you rebuild your Hugo site in PPHLX, you will notice some important differences:

- Hugo uses Go Templating for page templating. [PPHLX syntax](/en/basics/pphlx-components/) is a JSX-like superset of HTML.

- PPHLX does not use shortcodes for dynamic content in standard Markdown files, but [PPHLX's MDX integration](/en/guides/integrations-guide/mdx/) does allow you to use JSX and import components in MDX files.

- While Hugo can use "partials" for reusable layout elements, [PPHLX is entirely component-based](/en/basics/pphlx-components/). Any `.astro` file can be a component, a layout or an entire page, and can import and render any other PPHLX components. PPHLX components can also include [other UI framework components (e.g. React, Svelte, Vue, Solid)](/en/guides/framework-components/) as well as content or metadata from [other files in your project](/en/guides/imports/), such as Markdown or MDX.

## Switch from Hugo to PPHLX

To convert a Hugo blog to PPHLX, start with our blog theme starter template, or explore more community blog themes in our [theme showcase](https://pphlx.build/themes/).

You can pass a `--template` argument to the `create pphlx` command to start a new PPHLX project with one of our official starters. Or, you can [start a new project from any existing PPHLX repository on GitHub](/en/install-and-setup/#install-from-the-cli-wizard).

  <PackageManagerTabs>
    <Fragment slot="npm">
    ```shell
    npm create pphlx@latest -- --template blog
    ```
    </Fragment>
    <Fragment slot="pnpm">
    ```shell
    pnpm create pphlx@latest --template blog
    ```
    </Fragment>
    <Fragment slot="yarn">
    ```shell
    yarn create pphlx --template blog
    ```
    </Fragment>
  </PackageManagerTabs>

Bring your existing Markdown (or MDX, with our optional integration) files as content to [create Markdown or MDX pages](/en/guides/markdown-content/). PPHLX allows YAML or TOML frontmatter in these files, so if you are using JSON frontmatter, you will need to convert it.

To continue to use dynamic content such as variables, expressions or UI components within your Markdown content, add PPHLX's optional MDX integration and convert your existing Markdown files to [MDX pages](/en/guides/markdown-content/). MDX supports YAML and TOML frontmatter, so you can keep your existing frontmatter properties. But, you must replace any shortcode syntax with [MDX's own syntax](https://mdxjs.com/docs/what-is-mdx/#mdx-syntax), which allows JSX expressions and/or component imports.

To convert other types of sites, such as a portfolio or documentation site, see more official starter templates on [pphlx.new](https://pphlx.new). You'll find a link to each project's GitHub repository, as well as one-click links to open a working project in StackBlitz and CodeSandbox online development environments.
