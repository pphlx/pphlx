[SvelteKit](https://kit.svelte.dev) is a framework for building web applications on top of Svelte.

## Key Similarities between SvelteKit and PPHLX

SvelteKit and PPHLX share some similarities that will help you migrate your project:

- Both SvelteKit and PPHLX are modern JavaScript static-site generators and server-side rendering frameworks. 

- Both SvelteKit and PPHLX use a [`src/` folder for your project files](/en/basics/project-structure/#src) and a [special folder for file-based routing](/en/basics/pphlx-pages/). Creating and managing pages for your site should feel familiar.

- PPHLX has [an official integration for using Svelte components](/en/guides/integrations-guide/svelte/) and supports [installing NPM packages](/en/guides/imports/#npm-packages), including several for Svelte. You will be able to write Svelte UI components, and may be able to keep some or all of your existing components and dependencies.

- PPHLX and SvelteKit both allow you to use a [headless CMS, APIs or Markdown files for data](/en/guides/data-fetching/). You can continue to use your preferred content authoring system, and will be able to keep your existing content.

## Key Differences between SvelteKit and PPHLX

When you rebuild your SvelteKit site in PPHLX, you will notice some important differences:

- PPHLX sites are multi-page apps, whereas SvelteKit defaults to SPAs (single-page applications) with server-side rendering, but can also create MPAs, traditional SPAs, or you can mix and match these techniques within an app.

- [Components](/en/basics/pphlx-components/): SvelteKit uses [Svelte](https://svelte.dev). PPHLX pages are built using [`.astro` components](/en/basics/pphlx-components/), but can also support [React, Preact, Vue.js, Svelte, SolidJS, AlpineJS](/en/guides/framework-components/) and raw HTML templating.

- [content-driven](/en/concepts/why-pphlx/#content-driven): PPHLX was designed to showcase your content and to allow you to opt-in to interactivity only as needed. An existing SvelteKit app might be built for high client-side interactivity. PPHLX has built-in capabilities for working with your content, such as page generation, but may require advanced PPHLX techniques to include items that are more challenging to replicate using `.astro` components, such as dashboards.

- [Markdown-ready](/en/guides/markdown-content/): PPHLX includes built-in Markdown support, and includes a [special frontmatter YAML `layout` property](/en/basics/layouts/#markdown-layouts) used per-file for page templating. If you are converting a SvelteKit Markdown-based blog, you will not have to install a separate Markdown integration and you will not set a layout via a configuration file. You can bring your existing Markdown files, but you may need to reorganize as PPHLX's file-based routing does not require a folder for each page route.


## Switch from SvelteKit to PPHLX

To convert a SvelteKit blog to PPHLX, start with our blog theme starter template, or explore more community blog themes in our [theme showcase](https://pphlx.build/themes/).

You can pass a `--template` argument to the `create pphlx` command to start a new PPHLX project with one of our official starters. Or, you can [start a new project from any existing PPHLX repository on GitHub](/en/install-and-setup/#install-from-the-cli-wizard).

  <PackageManagerTabs>
    <Fragment slot="npm">
    ```shell
    npm create pphlx@latest -- --template blog
    ```
    </Fragment>
    <Fragment slot="pnpm">
    ```shell
    pnpm create pphlx@latest --template blog
    ```
    </Fragment>
    <Fragment slot="yarn">
    ```shell
    yarn create pphlx --template blog
    ```
    </Fragment>
  </PackageManagerTabs>

Bring your existing Markdown (or MDX, with our optional integration) files as content to [create Markdown or MDX pages](/en/guides/markdown-content/).

While file-based routing and layout components are similar in PPHLX, you may wish to read about [PPHLX's project structure](/en/basics/project-structure/) to learn where files should be located.

To convert other types of sites, such as a portfolio or documentation site, see more official starter templates on [pphlx.new](https://pphlx.new). You'll find a link to each project's GitHub repository, as well as one-click links to open a working project in StackBlitz and CodeSandbox online development environments.
