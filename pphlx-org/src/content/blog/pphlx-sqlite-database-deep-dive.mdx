When websites scale to tens of thousands of pages, in-memory metadata storage can run out of memory. 

To solve this, **PPHLX** embeds SQLite inside its Go compiler. This post takes a technical look under the hood at how PPHLX configures, indexes, and queries this local content database.

## Embedding SQLite in the Go Compiler

By leveraging Go's native SQLite bindings, PPHLX mounts a local database file (`.PPHLX/content.db`) during compilation. When you run `PPHLX build`:

1.  **Ingestion**: Loaders read Markdown files, remote CMS APIs, or JSON datasets.
2.  **Schema Check**: Fields are parsed and checked using Zod definitions.
3.  **On-Disk Sync**: Validated records are written into indexed SQLite tables.
4.  **PHP Serialization**: A static metadata snapshot is exported so that your dynamic PHP layouts can read records from a fast local cache table without making expensive network calls.

## Writing SQL Queries

Because your collections are written to an actual SQLite file, you can use standard SQL expressions to filter your content:

```ts
import { getCollection } from 'PPHLX:content';

// Fetch only active hardware products costing less than $100
const saleProducts = await getCollection('products', {
  where: "category = 'hardware' AND price < 100",
  orderBy: "price ASC",
  limit: 10
});
```

This ensures that only matching entries are loaded into the page generation process, keeping your memory usage minimal and compile times extremely short.
