When building global applications, providing localized layouts is critical. In traditional Single Page Applications (SPAs), translating pages usually means shipping huge JSON dictionaries to the browser, which slows down loading times.

In **PPHLX**, internationalization (i18n) is handled **server-first**. The compiler handles routing and layout rendering natively on the PHP backend, ensuring users get fully translated pages instantly.

## Server-Side Translations in `.pphx`

Because PPHLX compiles directly to native PHP templates, you can hook your page layout directly into your existing PHP localization files or systems (like WordPress translation hooks or WHMCS language directories):

```pphx
@import LanguageSelector from '../components/LanguageSelector.vue'

<div class="header">
  <LanguageSelector />
  <h1>{|= get_lang_string('welcome_message') |}</h1>
</div>
```

The compiler outputs this as a standard, high-performance `.php` file. The server translates the header text before sending the HTML to the client.

## Localized Component Islands

For interactive client-side components (like Svelte forms or React buttons), PPHLX allows passing the translated strings directly as props from your server layout:

```pphx
@import UserProfile from '../components/UserProfile.jsx'

<UserProfile 
  label="{|= get_lang_string('profile_label') |}" 
  logoutText="{|= get_lang_string('logout_action') |}" 
/>
```

This guarantees that the browser never has to fetch separate locale files or load translation runtimes. Your interactive widgets receive pre-translated strings natively on load, keeping client bundles lightweight and fast.
