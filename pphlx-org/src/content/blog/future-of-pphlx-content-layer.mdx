With the initial release of PPHLX Content Collections, we introduced frontmatter schema validation and a simple, type-safe API for local Markdown files.

But websites often need to scale, pulling content from remote databases, legacy CRM tables, or headless CMS platforms. Doing this dynamically at request-time can crash your PHP server or introduce significant performance latency.

To address this, we are planning the next evolution of our content engine: **The PPHLX Content Layer**.

## Embedded SQLite for Massive Scale

To prevent high memory usage when projects scale to tens of thousands of content pages, we are exploring [LibSQL](https://github.com/tursodatabase/libsql) (SQLite) as the underlying storage engine inside the PPHLX Go compiler.

By embedding SQLite directly in the Go compiler binary:
*   We can cache millions of entries on-disk between compilation cycles.
*   We can speed up build times by only fetching delta updates.
*   We can expose powerful SQL querying capabilities (filters, sorts, and joins) to developers directly inside their templates.

## A Pluggable Loader Ecosystem

Rather than restricting content collections to the `src/content/` directory, we are building a pluggable data loader API:

```ts
import wordpressLoader from 'PPHLX-wordpress-loader';

defineCollection({
  name: 'articles',
  loader: wordpressLoader({
    endpoint: 'https://mysite.com/wp-json',
  }),
});
```

This allows developers to import reusable loaders from npm to fetch data from any external API (like Shopify, WooCommerce, or direct database connections) and write them directly into local cache tables, serving them via native, high-performance PHP layouts.
