WordPress powers over 40% of all websites. While the Core platform has evolved, developers building custom WordPress themes or plugins face a divided workflow:

1.  **Gutenberg & React Overhead**: The Block Editor (Gutenberg) is built on React, which requires developers to set up complicated webpack, Babel, and Node.js compilation configurations just to output a custom theme block.
2.  **Plugin UI Fragmentation**: Building administrative settings panels or dynamic frontends typically results in writing messy jQuery scripts or fighting with SPA routers that don't respect WordPress core files.
3.  **Performance Trade-offs**: Traditional headless configurations require decoupling WordPress (running on PHP) from the frontend (running on Next.js/Vite), introducing hosting overhead and complicating SEO.

With **PPHLX**, we offer a unified, modern workflow. You can author your themes and plugins using Svelte, React, or Vue component islands and compile them directly to WordPress-compatible PHP structures.

## Compiling Svelte and React Into WordPress Themes

Instead of separating your frontend from your WordPress installation, PPHLX compiles your `.pphx` layouts directly into standard WordPress template files (like `single.php` or `page.php`):

```pphx
@import Navigation from '../components/Navigation.svelte'
@import PostStats from '../components/PostStats.vue'

<div class="wp-site-header">
  <Navigation client:load />
</div>

<main class="post-content">
  <h1>{|= get_the_title() |}</h1>
  <div class="body">
    {|= get_the_content() |}
  </div>
  <PostStats postID="{|= get_the_ID() |}" client:visible />
</main>
```

When you compile this template, PPHLX outputs a clean `.php` file and registers static JS/CSS bundles. WordPress handles the routing, database access, and core queries natively on the server, while Svelte and Vue hydrate client-side interactivity automatically.

## Native Integration with WordPress Hooks

Because PPHLX outputs standard PHP code, you can easily tie your component rendering into the WordPress action and filter lifecycle (`add_action`, `add_filter`):

```pphx
{|
// Example: Register a custom shortcode to render our Vue weather widget
add_shortcode('PPHLX_weather', function($atts) {
    ob_start();
    ?>
    @import WeatherWidget from '../components/WeatherWidget.vue'
    <WeatherWidget location="{|= esc_attr($atts['location']) |}" client:load />
    <?php
    return ob_get_clean();
});
|}
```

During compilation, PPHLX registers the `WeatherWidget` asset bundle and outputs the shortcode hook, making the interactive island available anywhere inside Gutenberg posts.

## Zero-Config Gutenberg Blocks

By compiling React or Svelte component files into isolated JS elements, PPHLX lets you output Gutenberg block structures without managing webpack configs. You write your blocks using clean, modular code, and the Go compiler does the heavy lifting, producing standard plugin code ready to be published to the WordPress Plugin Directory.
